# UQ-002 — نمایش صریح انرژی مالی و PDF مستقل

## Intake / Discover
نوع: غیرپژوهشی، فقط presentation. کاربر پنل مالی می‌خواهد P90 انرژی را به‌عنوان احتمال تجاوز ببیند، نه q90. معیار موفقیت: در دادهٔ مصنوعی q10=70، q50=100 و q90=130، حالت صریح P90=70 نشان دهد؛ حالت خاموش همان نمایش قبلی را حفظ کند.

`FinancialTab` نتیجهٔ موقت `FinancialUqResult` دارد؛ `OfficialReportModal` این نتیجه را دریافت نمی‌کند. فرض محافظه‌کارانه: گزارش اصلی پروژه را به UQ موقت متصل نکنیم. PDF جدید snapshot مستقل است، نه تغییر گزارش اصلی، annual yield یا ورودی مالی. source فقط خروجی legacy مالی و trace ID همان اجراست؛ این شناسه hash پروژه یا اثبات صحت نیست.

## Plan / Design
1. view مشترک در `src/studies/financialEnergyQuantileView.ts`: adapter UQ-001 و ردیف‌های PDF، بدون تغییر مقدار.
2. کارت `FinancialEnergyQuantiles.tsx`: flag محلی `enabled` پیش‌فرض false؛ اتصال در FinancialTab فقط جای کارت انرژی قبلی. ذخیرهٔ flag در پروژه/localStorage وجود ندارد.
3. تست SSR فارسی/انگلیسی، readback واقعی PDF و تست Chromium مؤلفه با React واقعی.
4. gate خودکار شامل رگرسیون UQ-001/انرژی/هسته، typecheck، build و تست‌های جدید.

قرارداد ورودی: MetricDistributionOutput انرژی با واحد MWh از annualGenerationMwh و traceId اجرا. هزینه و NPV وارد adapter نمی‌شوند. خروجی: display یا standalone PDF با schemaVersion، source، provenance، validationStatus و محدودیت‌ها. API شبکه، محاسبهٔ مدل، سرویس Python یا auth جدید لازم نیست؛ این تغییر هیچ endpoint جدیدی ندارد.

## وضعیت‌های UI و شکست
- خاموش: مقدار/عنوان قدیمی انرژی؛ button export جدید وجود ندارد.
- روشن و معتبر: دو سطر مجزای energy-exceedance و CDF؛ منشأ و محدودیت؛ دکمهٔ PDF مستقل.
- روشن و نامعتبر: alert، بدون مقدار صریح یا export؛ exception خام یا دادهٔ حساس لاگ نمی‌شود.
- export در حال اجرا: دکمه غیرفعال؛ شکست font/export با alert و امکان retry.
- خاموش‌کردن flag: برگشت به نمایش قدیمی، بدون migration یا دست‌کاری state مالی.

PDF با lazy import و فونت بسته‌بندی‌شده تولید می‌شود؛ نیاز به اینترنت بیرونی ندارد. export فقط یک گزارش کوتاه است؛ محاسبهٔ MC جدیدی در UI اجرا نمی‌شود. اجرای سنگین UQ قدیمی در این چرخه بازطراحی نشده است. PDF شروع‌شده snapshot همان لحظه است؛ تغییرات بعدی آن را به‌روز نمی‌کند.

## Acceptance criteria
- پیش‌فرض خاموش و fallback مقدارهای سابق، در fa/en.
- نگاشت روشن دقیق P10=130/P50=100/P90=70 MWh با CDF جدا.
- همان view در PDF؛ readback متن شامل P90/q10، مقدار، trace ID، نسخه و not_field_validated.
- ورودی/محاسبات mutate نشوند؛ هیچ callback برای finance یا research adoption در مؤلفه نیست.
- دادهٔ نامعتبر export نداشته باشد؛ شکست فونت خطای retryable بدهد.
- تست‌های جدید، رگرسیون‌های انتخاب‌شده، build و types با exit=0؛ gate تنها برای این دامنه ready-for-review بدهد.

## Verify / Reflect
تست PDF ابتدا به دلیل شکستن عبارت بلند بین سطرها در استخراج متن شکست خورد. scope به ردیف‌های کوتاه و مجزا تقسیم شد تا جملهٔ عدم پذیرش پژوهش خوانا و قابل تست باشد؛ تست PDF واقعی دوباره سبز شد. Chromium مؤلفهٔ واقعی را در harness مستقل mount می‌کند؛ این آزمون E2E کامل کل برنامه یا تأیید Safari واقعی نیست. build موفق است ولی هشدارهای chunk size و annotation وابستگی‌ها باقی است؛ ادعای رفع آن‌ها نداریم.

## راهنمای کاربر
در تب مالی، پس از اجرای UQ، گزینهٔ «نمایش صریح احتمال تجاوز انرژی (آزمایشی)» را روی کارت انرژی فعال کنید. P90 محافظه‌کارانهٔ تولید در کنار CDF نمایش داده می‌شود. دکمهٔ «PDF مستقل صدک انرژی» snapshot همان نتیجه را می‌دهد. برای برگشت گزینه را خاموش کنید. LCOE و NPV در این چرخه تغییر نکرده‌اند؛ معنا و برچسب قدیمی آن‌ها همچنان موضوع چرخهٔ مستقل بعدی است.

## دقت و منشأ
مقادیر گرد‌شدهٔ موتور قبلی عیناً حفظ می‌شوند؛ دقت انرژی افزایش نمی‌یابد. P50 میانه است، نه لزوماً میانگین. horizon، CV یا صحت دادهٔ پروژه در این adapter تأیید نمی‌شود. هیچ P75/P99 یا گواه بانک‌پذیری تولید نمی‌شود. گزارش اصلی پروژه تغییر نکرده است.

رسید: `docs/audit/UQ-002-GATE.json`.

- رگرسیون و مرجع عددی؟ UQ-001 با oracle تحلیلی حفظ شده؛ تست‌های جدید mapping و export را می‌سنجند، نه اعتبار میدانی.
- محدودیت/دقت/منشأ؟ در UI، PDF و این سند وجود دارد.

## Changelog / Learn
افزودن view و مؤلفه، جایگزینی فقط کارت انرژی، تست‌های UI/PDF و gate. بدون migration یا تغییر فرمول.
باقی‌مانده: آزمون E2E کل پنل روی پلتفرم‌های هدف، بازبینی برچسب‌های هزینه/NPV و risk category، snapshot هویت پروژه/ابطال نتایج stale و تصمیم مستقل برای نمایش پیش‌فرض. خاموش‌بودن flag عمداً معنای قدیمی را باقی می‌گذارد؛ این تغییر رفع سراسری نام‌گذاری نیست. مانع‌های عمومی مجوز و Safari مربوط به انتشار کل محصول همچنان جدا هستند.

## بازبینی مجدد و اصلاح اتصال واقعی
- نقص کشف‌شده: engine واحد `MWh/year` می‌دهد ولی fixture فقط MWh بود. قرارداد اکنون این واحد را **بدون تبدیل یا سالانه‌سازی** حفظ می‌کند؛ برچسب `/year` اعلام منبع است نه اثبات پوشش سالانه.
- تست جدید خروجی واقعی `runFinancialUncertaintyPropagation` را به view/PDF می‌برد. آزمون Chromium اکنون خود FinancialTab را با financial engine واقعی mount می‌کند، UQ را اجرا و نمایش MWh/year را بررسی می‌کند.
- نتیجهٔ موقت UQ به snapshot ورودی‌های مالی/قیمت/سایت/هندسه بسته شد؛ تغییر ورودی نتیجه را فوراً مخفی و timer منتظر را لغو می‌کند. تست تغییر قیمت و مخفی‌شدن کارت اضافه شد.
- export در حال ساخت با خاموش‌شدن flag یا unmount اجازهٔ download ندارد. PDF تحویل‌داده‌شدهٔ قبلی خودکار پس گرفته نمی‌شود.
- این پوشش، integration واقعی تب در harness است، نه E2E کل App و نه native Safari. مانع Safari بومی/مجوز انتشار عمومی با این کار حل‌شده اعلام نمی‌شود.
