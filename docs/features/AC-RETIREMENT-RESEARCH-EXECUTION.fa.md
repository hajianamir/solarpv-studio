# حذف ورودی‌های AC و اجرای قابل‌فهم مطالعات پژوهشی

این سند قرارداد جدید را جایگزین قسمت‌های مربوط به حفظ فرم AC در `RESEARCH-WORKSPACE-SPEC.fa.md` می‌کند. تغییرات وابستگی‌های npm در همین شاخه کار قبلی و مستقل‌اند و حفظ شده‌اند.

## ۱. قرارداد حذف AC

«الزامات الکتریکی AC — ورودی صریح کاربر» در هیچ خانواده/حالت پروژه نمایش داده نمی‌شود. حذف فقط ظاهری نیست:

| مسیر قبلی | رفتار جدید |
|---|---|
| state و ذخیرهٔ `acRequirements` | حذف از state، snapshot، schema جاری و خروجی ذخیره |
| ورود پروژهٔ قدیمی | کنارگذاری دادهٔ بازنشسته با هشدار و تأیید کاربر؛ دادهٔ قدیمی حتی با مقدار نامعتبر ورودی موتور نمی‌شود |
| جریان بار از سرویس/override قدیمی | حذف؛ توان/انرژی/فاز از خود بارها. جریان ۲۳۰/۴۰۰ ولت با PF=1 فقط فرض نمایشی و با برچسب روشن باقی است |
| فاز/PF خوشه اینورتر از فرم قدیمی | فاز از بارهای AC، فاز تجهیزات از کاتالوگ؛ PF نامعلوم به kVA تأییدشده تبدیل نمی‌شود |
| تأیید تزریق به‌عنوان پیش‌شرط آرایش MV | حذف وابستگی؛ ظرفیت، فناوری و ولتاژ مثبت کلکتور ورودی مستقل طراحی مقدماتی‌اند، نه مجوز اتصال شرکت برق |
| محاسبهٔ کابل AC با دو فرم تکراری | فقط ورودی کامل هر فیدر و تطابق فاز/ولتاژ با کاتالوگ اینورتر؛ طول، جریان، جنس، نصب، PF، مشخصات کلید، سطح خطا و زمان قطع همچنان لازم‌اند |
| BOM کلید AC | بدون ارزیابی فیدر، کلید انتخاب نمی‌شود؛ در مسیر ارزیابی‌شده، جریان/قدرت قطع/مرجع از دادهٔ همان فیدر است، نه مقدار ثابت 50kA |
| SLD و گزارش | حذف جدول/متن الزامات و تأییدهای قدیمی؛ دادهٔ کاتالوگ به‌عنوان کاتالوگ، جریان نمایشی و وضعیت بررسی‌نشده صریح‌اند |
| موتور `acRequirements.ts` | حذف کامل؛ هیچ importer فعالی باقی نیست |

روابط فیزیکی مستقل کابل و بار حذف نشده‌اند. حذف نام AC از همهٔ علوم برق منظور این قرارداد نیست؛ حذف سیستم ورودی تکراری و وابستگی‌های آن است. بخش‌های مستقل تحلیل شبکه، کابل و مطالعات PVlib همچنان ورودی‌های ضروری خود را دارند.

### اثر محاسباتی و مرز مالی

معادلات انرژی/مالی بازنویسی نشده‌اند؛ اما حذف ورودی سابق و حذف شرط تأیید تزریق **ممکن است نتیجهٔ بازمحاسبهٔ پروژهٔ قدیمی را تغییر دهد**، مثلاً شمار اینورترها پس از مشخص‌کردن کلکتور MV. مهاجرت این موضوع را پیش از اعمال اعلام می‌کند؛ نتیجهٔ قدیمی را با نتیجهٔ جدید برابر فرض نکنید. فایل قدیمی اصلی را نگه دارید. هیچ نتیجهٔ پژوهشی خودکار وارد انرژی/مالی نمی‌شود و gate تطابق زمینهٔ مطالعات عملیاتی پابرجاست.

## ۲. پژوهش: نمونه با مطالعهٔ اجراشده فرق دارد

کد قبلی نمونه را فقط در ویرایشگر JSON می‌گذاشت. اجرای واقعی endpoint و Python وجود داشت، اما سرویس/پرچم مدل می‌توانست غیرفعال باشد و UI صرفاً یک دکمهٔ غیرفعال نشان می‌داد. بارگذاری مثال اجرای محاسبه نیست و نباید بدون اطلاع کاربر کار سنگین یا احرازنشده آغاز کند.

اکنون:

1. یک موضوع و مثال را انتخاب کنید؛ **فرم پارامترها** نمایش داده می‌شود. نام و واحدهای فیلد مطابق قرارداد خود مدل‌اند و از مدل دیگری حدس زده نمی‌شوند.
2. پارامترها را ویرایش کنید. ورودی خارج از دامنه اجرا را متوقف می‌کند، اما فرم برای اصلاح مقدار باقی می‌ماند.
3. وضعیت سرور علت دقیق توقف را اعلام می‌کند: دریافت وضعیت، خطای ارتباط، غیرفعال‌بودن سرویس، پرچم مدل یا نبود پیکربندی احراز هویت. «بررسی دوبارهٔ سرور» بدون reload قابل استفاده است.
4. پس از آماده‌بودن، **Run research** را بزنید. مطالعه در سرور/Python اجرا می‌شود؛ بارگذاری نمونه یا اعلام enabled اثبات نصب runtime نیست.
5. خروجی محاسبه‌شده به‌شکل جدول همراه با شناسهٔ عملیات، manifest محیط و hash کد نمایش داده می‌شود. JSON خام و ویرایش طرح در بخش پیشرفته قرار دارند. دادهٔ کامل با دانلود نتیجه/آرشیو در دسترس است.
6. خطاهای 401 راهنمای توکن و خطاهای 502/503 راهنمای محیط/پرچم دارند؛ هیچ خطا به نتیجهٔ ساختگی یا fallback موفق تبدیل نمی‌شود.

فرم حداکثر ۱۶۰ فیلد را نشان می‌دهد؛ سری‌های بزرگ‌تر از ۲۴ عضو از ویرایشگر پیشرفته مدیریت می‌شوند. نمایش نتیجه حداکثر ۱۲۰ ورودی و ۲۰ عضو اول آرایه را دارد؛ فایل کامل محدود به این نمایش نیست. تغییر ورودی/موضوع، ورود آرشیو و خروج از ابزار نتیجه را نامعتبر یا کار را لغو می‌کند؛ پاسخ دیررس نتیجهٔ جاری نمی‌شود. آرشیو بازیابی‌شده اجرای تازه به حساب نمی‌آید.

### راه‌اندازی سرور برای اجرای واقعی

محیط Node به‌تنهایی موتورهای علمی را نصب/فعال نمی‌کند. `.env.example` اکنون تنظیمات اختیاری را مستند دارد؛ مقادیر محرمانه در فایل نمونه نیستند.

Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r services/pvlib_research/requirements.txt
```

Windows (از پوشهٔ پروژه):

```bat
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r services\pvlib_research\requirements.txt
```

در محیط سرور `PVLIB_PYTHON` را به مسیر کامل مفسر نصب‌شده تنظیم و `PVLIB_RESEARCH_ENABLED=true` را فعال کنید؛ سپس سرور را دوباره اجرا کنید. برای هر خانواده، پرچم دقیق در UI اعلام می‌شود. PyBaMM/مدل‌های مرجع نیازمند محیط/نیازمندی‌های اختصاصی مستند در `services/pvlib_research/README.md` هستند؛ فعال‌کردن پرچم، جای نصب runtime را نمی‌گیرد.

JWT یا gateway معتبر باید از سمت مدیر تنظیم شود. توکن کوتاه‌عمر را در ورودی Bearer وارد کنید؛ **JWT_SECRET کلید سرور است و نباید در مرورگر وارد شود**. هیچ endpoint جدیدی برای صدور عمومی توکن یا دورزدن احراز هویت اضافه نشده است. سرورِ تنظیم‌نشده عمداً اجرا نمی‌کند؛ وضعیت blocked این حالت، باگ محاسبات یا مطالعهٔ موفق نیست.

## ۳. قرارداد آزمون و نتایج

```sh
npm run lint
npm run build
npm test
npm run test:ac-retirement
npm run verify:help
npm run verify:exports
PVLIB_PYTHON="$PWD/.venv/bin/python" npx tsx scripts/test-research-browser.ts
PVLIB_PYTHON="$PWD/.venv/bin/python" npx tsx scripts/test-calibration-browser.ts
npx tsx scripts/test-research-workspace-browser.ts
npx tsx scripts/test-browser-regressions.ts
PVLIB_PYTHON="$PWD/.venv/bin/python" npx tsx scripts/test-research-api.ts
```

- پذیرش AC: نبود فرم در حالت‌ها، حذف از ذخیره/خروجی/بازیابی، بی‌اثری payload قدیمی حتی با مقدار متناقض، نگهداشت MV و ورودی مستقل فیدر و عدم ادعای طراحی کابل با دادهٔ ناقص.
- پذیرش پژوهش: فرم بدون بازکردن JSON، ویرایش/اصلاح مقدار نامعتبر، اجرای واقعی Python با مقدار فرم و بررسی requestCanonicalJson و codeSha256، نتیجهٔ جدولی و JSON خام پیش‌فرض بسته؛ سپس thermal/circuit/integrated، JWT، archive، cancel/stale و کالیبراسیون واقعی.
- رگرسیون: شش benchmark و آزمون‌های هسته، گزارش‌های DOCX/XLSX/JSON، workflow مرورگر و fa/en/mobile/RTL. محاسبات Python روی نمونه‌های فرضی/مرجع هستند، نه اثبات دقت میدانی جدید.

برای بازتولید گیت یکپارچه با Python نصب‌شده: `PVLIB_PYTHON="$PWD/.venv/bin/python" npx tsx scripts/verify-research-workspace.ts`. این فرمان اکنون قرارداد جدید را می‌سنجد و رسید قدیمی را بازنویسی نمی‌کند.

رسید جدید: `docs/audit/AC-RETIREMENT-RESEARCH-GATE.json`. رسیدهای قبلی، از جمله رسید تفکیک اولیهٔ workspace، تاریخی و مربوط به hashهای قبلی‌اند. همهٔ مدل‌های اختیاری و تمام مثال‌های ۱۳ موضوع در این چرخه **از نظر عددی اجرا نشده‌اند**؛ مرور فرم/مثال با اجرای عددی متفاوت است. Native Windows/Safari در این محیط Linux آزموده نشده‌اند. lint دارای هشدارهای موجود no-explicit-any است؛ خطای lint پذیرفته نمی‌شود.

## ۴. rollback

تغییرات این قابلیت را در App، schema/migration، گزارش/SLD، حفاظت فیدر، help و ResearchEditor/ResearchStudyView و تست‌های مرتبط با هم بازگردانید. تغییرات مستقل npm را لازم نیست برگردانید. فایل‌های قدیمیِ اصلی را نگه دارید: فایل تازهٔ ذخیره‌شده دیگر دادهٔ `acRequirements` را ندارد و rollback آن داده را از هیچ نمی‌سازد. feature flag پژوهش همچنان runtime را خاموش می‌کند؛ حذف فرم AC تصمیم محصول است و پرچم مخفی برای احیای آن ندارد.
