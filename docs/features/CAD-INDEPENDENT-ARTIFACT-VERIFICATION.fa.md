# بررسی مستقل مؤلفه‌ای DXF و هندسهٔ CAD

## دامنه و معیار پذیرش
این مرحله ادامهٔ اصلاح جانمایی بر مبنای `71a7c2b` است. هدف آن بررسی فایل واقعی با پیاده‌سازی خارجی است، نه افزودن یک نسخهٔ دیگر از الگوریتم بسته‌بندی میزها یا معرفی فرض داخلی به‌عنوان استاندارد.

- **EXT-01:** فایل R2000/AC1015 با `ezdxf==1.4.3` بدون recovery خوانده شود؛ auditor هیچ error یا fix لازم نداشته باشد.
- **EXT-02:** واحد متر در خود فایل تعریف و handleها یکتا و تکرارپذیر باشند. دو خروجی برای یک جانمایی بایت‌به‌بایت برابر باشند.
- **EXT-03:** Shapely/GEOS اعتبار سطح‌ها، قرارگیری در سایت، عدم اشتراک میز/راه/پست و اتصال غیرنقطه‌ای راه‌ها را از چندضلعی‌های خوانده‌شده بررسی کند. شمار و سطح‌ها با مدل تطبیق یابند؛ تطبیق با مدل «شاهد یکپارچگی» است، نه مرجع مستقل تعداد بهینهٔ میز.
- **EXT-04:** ذخیره و خواندن مجدد به‌وسیلهٔ ezdxf تعداد، واحد و هندسه را حفظ کند.
- **EXT-05:** نمونه‌های منفی به دلیل مشخص رد شوند: subclass مفقود، واحد مفقود، handle تکراری، اتصال نقطه‌ای راه و پست روی راه حتی وقتی مدل و فایل هر دو همان خرابی را دارند.
- **EXT-06:** فهرست عبارت‌های تغییرکرده با کد فعلی کامل و همگام باشد؛ طبقه‌بندی این فهرست هیچ موردی را از گیت رسمی مستثنا نکند.

## نقص واقعی یافت‌شده و اصلاح
در ابتدای این مرحله، parser خارجی با خطای `DXFStructureError: missing 'AcDbPolyline' subclass in LWPOLYLINE` متوقف شد. parser داخلی قبلی تنها مختصات/لایه‌ها را می‌خواند و این نقص قالب را نمی‌دید.

اکنون entityها دارای subclassهای نوع مربوط، جدول LAYER دارای header/recordهای مشخص و handleهای مجزا هستند. `$INSUNITS=6` واحد متر و `$MEASUREMENT=1` مبنای متریک را مشخص می‌کند. handleهای تصادفی ۲۴بیتی با شمارندهٔ محلی قطعی جایگزین شدند؛ `$HANDSEED` مقدار بعدی را دارد. خروجی دیگر به شانس برخورد handle وابسته نیست. خواندن با ezdxf و auditor بدون تعمیر و round-trip آزموده می‌شود. این نتیجه به‌تنهایی تأیید تمام نسخه‌های AutoCAD یا انطباق کامل با هر بند استاندارد فایل نیست.

## استقلال و حدود شواهد
- آزمون روی **خروجی تحت آزمون** اجرا می‌شود؛ هیچ golden target از خروجی TypeScript ساخته یا در registry ثبت نشده است.
- parser و auditor از ezdxf و عملیات اشتراک/union/پوشش از GEOS استفاده می‌کنند؛ روابط بازه‌ای TypeScript در Python کپی نشده‌اند.
- همهٔ ۶۱ فایل واقعی با سه نوع سازه، سایت‌های کوچک/بزرگ/کشیده، راه صفر/۴/۱۲ متر و گام‌های پایین/اعشاری بررسی و round-trip می‌شوند.
- ده حالت منفی باید به دلیل مورد انتظار رد شوند؛ صرفِ رخ دادن یک exception دلخواه PASS نیست.
- حدود محاسبات هندسی `1e-7 m²` برای مساحت و `1e-7 m` برای طول صرفاً کران خطای عددی مختصات سانتی‌متری در مجموعهٔ آزمون‌اند؛ دقت نقشه‌برداری یا تلرانس اجرا نیستند.
- اندازهٔ پست، فاصله‌ها، حاشیه‌ها، حداقل span سایه و راهبرد ظرفیت، با این ابزارها اعتبار عمرانی/برقی/اقتصادی پیدا نمی‌کنند.

## اجرا و وابستگی‌ها
وابستگی‌های زیر **فقط برای آزمون** هستند؛ به runtime برنامه، موتور انرژی یا مالی افزوده نشده‌اند. فایل requirements تمام وابستگی‌های این محیط Python 3.11 را با نسخهٔ ثابت مشخص می‌کند؛ این فایل lock نسخه است، نه lock دارای hash برای همهٔ wheelهای پلتفرم‌ها.

```sh
python -m venv .venv
.venv/bin/python -m pip install -r scripts/cad_reference/requirements.txt
npm run test:cad:independent
npm run test:cad:evidence-review
```

در Windows از `.venv\Scripts\python.exe` برای نصب استفاده کنید. runner محیط محلی `.venv` را تشخیص می‌دهد؛ برای مفسر دیگر متغیر `CAD_REFERENCE_PYTHON` مسیر آن را مشخص می‌کند. نبود مفسر یا بستهٔ مرجع شکست است، نه skip موفق. فایل‌ها در دایرکتوری موقت سیستم ساخته و در پایان حذف می‌شوند. اجرای آزمون پس از نصب به شبکه نیاز ندارد. job مستقل CI نصب Python 3.11، بسته‌های ثابت و اجرای هر دو گیت را انجام می‌دهد؛ نتیجهٔ remote CI در این محیط ادعا نشده است.

## تفکیک گیت شواهد
`docs/audit/CAD-EXPRESSION-EVIDENCE-REVIEW.json` همهٔ عبارت‌های تغییرکرده نسبت به مبنا را با SHA-256 سورس ثبت می‌کند. در این مرحله، رفع قالب DXF چهار عبارت اضافی ایجاد کرده و تعداد از ۵۲ به **۵۶** رسیده است:

| گروه بررسی | تعداد | وضعیت استناد |
|---|---:|---|
| فرض/قاعدهٔ جانمایی | ۱۴ | آزمون پیامد هندسی؛ نه تأیید مقرراتی فرض |
| مشتق‌سازی هندسه یا شاخص | ۱۷ | آزمون داخلی و کنترل هندسهٔ خروجی؛ نه fixture مستقل تمام خروجی تابع |
| سریال‌سازی فایل | ۹ | parser/auditor و round-trip مستقل؛ نه حساسیت AST تک‌عبارت |
| قرارداد ورودی export | ۱ | آزمون رد پارامتر ناسازگار |
| قرارداد مرزی/امکان‌پذیری | ۱۳ | آزمون رفتاری و قیود هندسی |
| تجمیع چیدمان | ۲ | آزمون شمارش؛ نه اثبات بهینگی packing |

این طبقه‌بندی **مشورتی** است. manifest و منطق گیت مستقل تغییر نکرده‌اند و هیچ عبارت حذف/معاف نشده است. ادعای «۵۶ نقص» نیز از این شمار به دست نمی‌آید. تا ثبت و اجرای شواهد قابل‌قبول برای الزامات گیت، `test:all` نباید موفق اعلام شود. fixtureای که صرفاً دادهٔ برنامه را با همان فرض‌ها بازتولید کند، این کمبود را رفع نمی‌کند.

## بازبینی، مرز مالی و rollback
۱. مسیر entity/table/header با parser خارجی بررسی شد؛ سپس مورد شکست واقعی و audit بدون repair بازآزمایی شد.
۲. خروجی تحت آزمون با GEOS بررسی شد؛ سپس خراب‌سازی فایل و مدل به‌صورت هم‌زمان نشان داد که کنترل مستقل صرفاً به تطبیق داده‌ها متکی نیست.
۳. مرز ادعا و registry بررسی شد؛ سپس کنترل کامل‌بودن inventory و آزمون منفی جلوگیری از برچسب PASS برای classification اضافه شد.

مسیر محاسبات انرژی/مالی، قواعد پذیرش Research و پارامترهای جانمایی این مرحله تغییر نکرده‌اند. اصلاح runtime فقط در serializer DXF است. rollback باید writer و آزمون قالب را هماهنگ در نظر بگیرد؛ بازگرداندن writer نامعتبر برای انتشار مجاز نیست. در صورت ضرورت، خروجی CAD را غیرفعال کنید تا writer قابل‌خواندن فراهم باشد. پایگاه پروژه یا schema ذخیره نیاز به migration ندارد. این آزمون‌های خارجی ادعای Docker، پلتفرم بومی یا تأیید اجرایی ایجاد نمی‌کنند.


## تکمیل کنترل مستقل حسابداری خروجی
- **EXT-07:** شمار ماژول از تعداد چندضلعی‌های میز در فایل × تعداد ماژول‌های پیکربندی محاسبه شود. ظرفیت DC از این شمار و توان ورودی، با `Decimal` و گردکردن نیم‌به‌بالا تا ۰٫۰۰۱ MW محاسبه و با خروجی مقایسه شود. این کنترل، تأیید مستقل انتخاب پیکربندی ماژول‌ها نیست.
- **EXT-08:** مساحت سایت از GEOS و تعداد ردیف‌ها/بیشترین میز در ردیف از مختصات واقعی فایل استخراج شود، نه از برچسب row/col مدل.
- **EXT-09:** خراب‌کردن جداگانهٔ تعداد ماژول، ظرفیت DC، مساحت، تعداد ردیف و میز در ردیف، هرکدام با دلیل مختص خود رد شود.

۱۵ حالت اضافی شامل پنج توان ماژول اعشاری/مرزی در سه زاویهٔ صفر/۴۵/۹۰ درجه است. نتیجهٔ محلی: ۶۱ فایل و ۱۰ آزمون منفی موفق. آزمون داخلی ۵۸ حالته، lint (صفر خطا، ۹۳ هشدار)، build و مرورگر تولیدی Chromium دوباره موفق شدند. گیت رسمی مرجع دوباره با کد ۱ متوقف شد و Docker همچنان `ENOENT` است. کنترل Decimal یک کنترل مؤلفه‌ای حسابداری است، نه مرجع مستقل تمام خروجی تابع یا تصویب فرض‌های جانمایی؛ به همین دلیل برای ۵۶ عبارت fixture صوری ثبت نشده است.

نقطهٔ توقف: این محیط موتور Docker یا socket آن را ندارد؛ نصب یک client به‌تنهایی آزمون runtime را معتبر نمی‌کند. تکمیل گیت مرجع نیازمند داده/محاسبهٔ مستقلِ قابل‌ردیابی و قابل‌اعمال به کل خروجی است، نه بازتولید سیاست اختصاصی برنامه در Python. بدون چنین شواهدی وضعیت انتشار مسدود باقی می‌ماند. هیچ تغییر runtime دیگری در این مرحله انجام نشده و rollback کنترل‌های جدید فقط آزمون‌ها/مستندات را شامل می‌شود.
