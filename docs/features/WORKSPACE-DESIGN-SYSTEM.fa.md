# بازطراحی یکپارچهٔ UI/UX فضای کار

## هدف و دامنه

ارتقای زبان بصری مشترک تمام برنامه، بدون تغییر محاسبات، schema مهندسی، پذیرش انرژی یا قواعد مالی. طراحی جدید بر خوانایی داده، سلسله‌مراتب واضح، فضای سفید/منفی، دسترس‌پذیری و استفادهٔ طولانی‌مدت مهندسی متمرکز است؛ ادعای قابل‌اندازه‌گیری «بهترین UI جهان» یا گواهی دسترس‌پذیری ندارد.

### تغییرات

- پوستهٔ تیره با سطوح سرمه‌ای/گرافیتی و پوستهٔ روشن با سطوح سفید و مرزهای نرم؛ آبی برای اقدام اصلی، سبز/کهربایی/قرمز برای معنای وضعیت حفظ شده‌اند.
- تیتر و توضیح زمینه‌ای هر صفحه، موقعیت پروژه، وضعیت منشأ انرژی و نوار مراحل از نظر سلسله‌مراتب جدا شده‌اند. هشدارها و محدودیت‌های علمی مخفی نشده‌اند.
- پیام‌های ذخیره/بازیابی در پایین صفحه ظاهر می‌شوند و دکمه‌ها را مسدود نمی‌کنند؛ وضعیت برای فناوری کمکی اعلام می‌شود.
- ناوبری گروه‌بندی‌شده با حالت فعال واضح و `aria-current`، آیکون‌های هماهنگ و نشانگرهای خوانا؛ خانوادهٔ پروژه انتخاب‌گر مستقل و دارای `aria-pressed` است.
- سربرگ و تله‌متری در یک shell چسبان؛ ارتفاع واقعی با ResizeObserver اندازه‌گیری می‌شود، نه فرض ثابت ۸۸ پیکسل. در RTL و LTR، سایدبار زیر shell می‌ماند.
- کارت‌ها، دکمه‌ها، فرم‌ها، جدول‌ها، fieldset، tabها، ورودی فایل و دیالوگ‌ها از اندازه و radius و فاصله‌گذاری مشترک استفاده می‌کنند. استایل جدید screen-only است؛ داده و قرارداد خروجی علمی/مالی تغییر نکرده است؛ فونت و radius ممکن است ظاهر یا صفحه‌بندی چاپ را تغییر دهند.
- تراکم **راحت / فشرده** با دکمهٔ بالای صفحه؛ فقط در `solarpv_ui_density` ذخیره می‌شود و بخشی از پروژه نیست. پوسته همچنان از انتخاب ذخیره‌شدهٔ کاربر استفاده می‌کند.
- فونت متغیر **Vazirmatn** برای فارسی و **Inter** برای انگلیسی و **JetBrains Mono** برای اعداد/کد از بسته‌های npm در build قرار می‌گیرند؛ Google Fonts از HTML حذف شده است. پس از نصب/build، نمایش متن به اینترنت وابسته نیست. فایل‌های مجوز OFL در `public/fonts/licenses/` قرار دارند.
- کنتراست متن ناوبری فعال و دکمهٔ اصلی در هر دو پوسته در آزمون به نسبت حداقل ۴٫۵:۱ بررسی می‌شود؛ این جای ممیزی کامل همهٔ ترکیب‌های رنگی را نمی‌گیرد.
- موبایل: انتخاب خانواده در ردیف مستقل، ابزارهای سربرگ قابل پیمایش افقی، فونت ۱۶px برای ورودی‌ها جهت جلوگیری از بزرگ‌نمایی ناخواستهٔ iOS، کنترل‌های راحت‌تر و سایدبار کشویی. منوی بسته در ترتیب فوکوس/نمایش نیست؛ منوی باز Escape و محصورسازی Tab دارد و پس از بستن، فوکوس به بازکننده برمی‌گردد.
- لینک پرش به محتوای اصلی، focus-visible و reduced-motion. وجود نام استانداردها دیگر با علامت تیکِ شبیه گواهی انطباق نمایش داده نمی‌شود؛ عبارت «مراجع طراحی؛ نه گواهی انطباق» جایگزین شده است.

## راهنمای کاربر

1. با آیکون خورشید/ماه، پوستهٔ روشن یا تیره را انتخاب کنید.
2. در دسکتاپ با دکمهٔ تراکم، بین خوانایی راحت و جدول‌های فشرده جابه‌جا شوید؛ انتخاب پس از reload حفظ می‌شود. در موبایل تراکم کنترل‌ها برای لمس مناسب نگه داشته می‌شود و دکمهٔ تراکم مخفی است.
3. در نمایشگر باریک، فهرست مراحل از دکمهٔ منو باز می‌شود. ابزارهای سربرگ در صورت کمبود جا افقی پیمایش می‌شوند؛ جدول‌های عریض نیز در ظرف خودشان پیمایش دارند، نه با کشیدن کل صفحه.
4. جستجوی Ctrl/Cmd+K، راهنمای F1، ذخیره و مسیرهای قبلی پروژه حفظ شده‌اند. انتخاب پوسته/تراکم پروژهٔ مهندسی را تغییر نمی‌دهد.
5. برای دریافت ظاهر و فونت‌های جدید از checkout به‌روز، روی ویندوز `install.bat` و سپس `start.bat`؛ سایر محیط‌ها `npm ci` و فرمان اجرای معمول را استفاده کنند. سرویس‌ورکر نسخهٔ تولیدی همچنان برای حفظ کار ذخیره‌نشده بدون reload اجباری به‌روز می‌شود.

## قرارداد پذیرش

1. TypeScript، lint، build و benchmarkها عبور کنند؛ فایل‌های موتور انرژی/مالی در این بازطراحی دست‌نخورده بمانند.
2. کنترل‌های مشترک، کارت‌ها، ناوبری و سلسله‌مراتب در هر دو پوسته و زبان خوانا باشند؛ هیچ هشدار ایمنی یا منشأ داده پنهان نشود.
3. آزمون production Chromium در fa/en، dark/light و عرض‌های ۳۲۰، ۳۹۰، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۴۴۰ و ۱۵۳۶ پیکسل اجرا شود. صفحهٔ کامل overflow افقی نداشته باشد؛ محتوای عریض در ظرف مستقل قابل پیمایش بماند.
4. shell و سایدبار پس از تغییر عرض/زبان با هم هم‌تراز بمانند. منوی موبایل قابل بستن با Escape و قابل استفاده با Tab باشد.
5. فونت‌های واقعی فارسی/انگلیسی و monospace با مسدودبودن درخواست‌های خارجی بارگذاری شوند؛ هیچ درخواست Google Fonts ارسال نشود. مجوز فونت‌ها همراه توزیع موجود باشد.
6. تراکم واقعاً اندازهٔ کنترل را تغییر دهد، پس از reload حفظ شود و snapshot پروژه قبل/بعد آن یکسان بماند.
7. reduced-motion رعایت شود؛ shell در حالت چاپ نمایش داده نشود. بازخوانی باینری گزارش‌ها و رگرسیون مرورگر قبلی عبور کنند.

## اجرای آزمون

```sh
npm run lint
npm run build
npm test
npm run test:ui
npm run verify:exports
npm run test:dependencies
npx tsx scripts/test-research-workspace-browser.ts
npx tsx scripts/test-browser-regressions.ts
```

برای اجرای سریالی تمام گیت‌ها و تولید رسید: `npx tsx scripts/verify-ui-refresh.ts`. هنگام این اجرا build دیگری را هم‌زمان اجرا نکنید؛ آزمون سرویس‌ورکر به ثابت‌بودن assetهای همان نسخه نیاز دارد.

اسکریپت `test:ui` از build تولیدی و Chromium واقعی استفاده می‌کند؛ نتایج و تصاویر بررسی بصری در `.cache/ui-refresh/` تولید می‌شوند و وارد Git نمی‌شوند. رسید تجمیعی این تغییر در `docs/audit/WORKSPACE-DESIGN-GATE.json` است. رسیدهای قدیمی AC/پژوهش/وابستگی‌ها مربوط به snapshotهای قبلی‌اند؛ hash جدید را از این رسید بخوانید.

### محدودیت پوشش

قواعد بصری مشترک کل برنامه را پوشش می‌دهند؛ این به معنی بازنویسی اختصاصی تک‌تک مولفه‌های قدیمی نیست. آزمون چیدمان روی صفحات نماینده و رگرسیون گردش‌کار انجام می‌شود، نه تمام ترکیب‌های محتوای دلخواه. صحت بصری همهٔ حالات WebGL/CAD، native Safari/iOS/Windows، screen reader واقعی، بزرگ‌نمایی همهٔ مرورگرها و انطباق کامل WCAG در این چرخه تأیید نشده است. نقشهٔ آنلاین در آزمون آفلاین ممکن است بدون tile باشد و این عمداً به تصویر ساختگی تبدیل نمی‌شود. بررسی چاپ در این آزمون به جداسازی shell محدود است، نه تضمین یکسان‌بودن همهٔ صفحات PDF. نام‌های فنی/واحدها و دادهٔ نمونه، اندازه‌گیری واقعی تلقی نمی‌شوند. این تغییر دقت علمی یا مالی جدیدی ادعا نمی‌کند.

## rollback

تغییرات این بازطراحی را در `src/styles/workspace.css`، importهای `src/main.tsx`، پوستهٔ `src/App.tsx`، فونت‌های `src/index.css`، radius/font-familyهای Tailwind، HTML و بسته/lockfile فونت‌ها با هم بازگردانید؛ تغییرات قبلی AC، پژوهش و ارتقای npm را حفظ کنید. در صورت بازگرداندن dependencyها، `npm ci` و build لازم است. کلید `solarpv_ui_density` صرفاً ترجیح نمایشی است؛ حذف اختیاری آن پروژه‌ها را پاک نمی‌کند. مهاجرت داده لازم نیست. پرچم runtime برای نسخهٔ قدیمی UI اضافه نشده؛ rollback از کد/بستهٔ قبل انجام می‌شود.
