## Numerical changes: F07/F08/F15/F17

- **F07:** ASHRAE IAM remains `max(0,min(1,1-b0*(sec(theta)-1)))`, with back-facing/grazing >=90° zero and six-decimal display/API rounding. Remove arbitrary85° and cos<=.01 early-zero policies. This is the published empirical equation, not a universal optical/material or annual-weather validation. Independent pinned `pvlib.iam.ashrae` vectors exercise small b0 at85–89°, where the old branch incorrectly returned zero. No default annual M&R policy changed.
- **F08:** Keep the legacy summary-extraction/DeSoto-style translation, approximate scalar Isc and80step MPP trace. Replace seed-dependent/exhaustible Voc Newton iteration and trace Newton iteration with monotone bracketed roots of `F(V,I)=Iph-I0*expm1((V+I*Rs)/a)-(V+I*Rs)/Rsh-I`. Positive translated parameters give monotonically decreasing F; Voc is bracketed on `[0,a*log(1+Iph/I0)]`; each generating current on `[0,Iph]`. Maximum128iterations, residual tolerance `1e-10+1e-12*Iph` A; invalid domain/bracket/nonfinite/exhaustion throws rather than returns a fake converged result. Endpoint current is0 only after solving unrounded Voc, and its actual residual is included in `solverDiagnostics` with max trace residual. Rounded point values are not used to claim tiny residuals. The public beta/gamma parameters remain for compatibility, not fitted constraints or seed controls. At the audit's extreme beta seed, old Voc188.23V becomes45.00V using identical translated parameters. Existing48case pvlib fixtures/3888trace points and separate72case explicit-reference suite remain in force. This is a legacy solver repair, not silent routing to the explicit reference API or annual/financial adoption.
- **F15:** MPPT compatibility decisions compare raw thermal voltage products, retaining two-decimal output fields for display. Any amount beyond a supplied voltage limit is infeasible; no display-rounding allowance creates a feasible result. Exact equality is accepted. This uses the same thermal/Vmp owner and disclosed proxy coefficients; no new coefficient/source is invented. The exact AST whitelist in phase1 is updated only for these known changes, not substituted for the independent-expression gate.
- **F17:** Solar azimuth uses `atan2(east,north)` of the local solar vector: east=`-cos(delta)*sin(H)`; north=`cos(phi)*sin(delta)-sin(phi)*cos(delta)*cos(H)`. No division by cos(latitude) and no near-pole constant azimuth branch. At numerically singular zenith/nadir (horizontal magnitude<1e-12), preserve180° as an explicit undefined-direction convention. Exact-pole direction uses local longitude frame, not a unique geographic north. Keep NOAA declination/equation-of-time and UTC/angle contracts unchanged; compare with independent pvlib SPA and original887ordinary-domain vectors. Real HTTP polar tests use the same independent oracle, not current engine output.
