# ADR-034 — Scenario resource/claim and row-report audit repairs

Date2026-11-03. Branch arena/9a79dcb1-solarpv-studio, base935b01a. Scope F05/F06/F13/F14/F21/F22 from the user-supplied incomplete audit. Not independent audit completion, model validation or conformity.

## Decisions

1. **Retire fabricated scenario metrics.** `reliabilityIndexPct` and `cableVoltageDropPct` remain named fields for discoverability but now return null for every scenario, with `reliabilityAssessment`/`electricalSafetyAssessment:not_assessed`. This is a deliberate nullable type correction: callers must not treat a preset as an evaluated probability/circuit result. The UI always displays availability as Not assessed, even if supplied an old-shaped scenario object containing a percentage. No availability estimator is invented without chronology, sources, loads and system topology.
2. **Remove false claims rather than add an unqualified replacement model.** Industrial narratives no longer assert continuous uptime, N+1/hot-standby, certified fire protection or coordinated SPDs. Additional PV/inverter budgets remain illustrative capacity/cost assumptions. Neutralize fixed lowest-TCO/superiority claims; do not claim a globally optimal design from a three-preset comparison. IDs remain stable, including `industrial_redundant`, solely for compatibility, not a verified redundancy statement. Battery life, cost and architecture labels are still unverified assumptions and the UI says so.
3. **Use supplied positive resource.** The existing generation proxy now uses supplied finite positive PSH directly, not max(1,PSH). Existing nonpositive unsizable handling and invalid/nonfinite fallback5.17 remain unchanged in this bounded fix, as do discount floor1%, cost/lifetime/degradation/replacement policies. These legacy assumptions are not endorsed as validated inputs. Expose `firstYearGenerationProxyKwh` and `scenario_generation_supplied_psh_v1` so the denominator is inspectable. This remains a scalar generation estimate, not served energy, reliability, matched site yield or new adoption eligibility.
4. **Restrict row claims to their actual calculation.** Keep pitch sizing unchanged. The report states a winter-solstice-noon ideal single-module-slant, level-ground screen; it no longer promises10–14clearance or cites IEC for that assertion. Report projected horizontal ground coverage uses selected module length, tilt and computed pitch rather than4.6m. Explicitly call it projected coverage, not slant/pitch GCR or the bifacial model's separate GCR. Missing module length is unavailable, not a fabricated dimension. Actual multi-module tables, orientation, row ends, terrain and full shadow chronology need a separately matched layout assessment.

Replacing the floor with an undocumented different minimum is rejected. Increasing pitch to match an unverified universal four-hour window is also rejected: time window, terrain, hemisphere, mounting and actual geometry are not universally supplied.

## Compatibility and rollback

No project input schema change. Scenario results are derived anew; old exported snapshots are historical, not authoritative assessed reliability. Nullable output fields require explicit handling by external consumers. Local guide/disclosures record the intentional low-resource LCOE change. Reverting numerical behavior requires a separately named/disclosed legacy policy and regression review; do not silently restore the floor. Claim corrections should remain even if numerical correction is rolled back. Never restore fabricated reliability or protection/compliance claims as compatibility behavior.
