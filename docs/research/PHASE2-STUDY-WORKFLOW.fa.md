# فاز ۲ — قرارداد داده و گردش منبع اجرایی

> وضعیت جدید پس از اصلاح دامنهٔ کاربر: این سند receipt تاریخی تحویل قبلی است. پوشش on-grid/off-grid، پاکت تک‌فایلی پروژه+شواهد، پیوست ساختاریافتهٔ EPC و شروع دفتر انرژی فاز ۳ اکنون پیاده‌سازی شده‌اند؛ راهنما و حدود پذیرش: [OPERATING-DISPATCH.fa.md](../OPERATING-DISPATCH.fa.md). موکول‌کردن حالت‌های غیرنیروگاهی در متن تاریخی زیر دیگر برنامهٔ جاری نیست.

## وضعیت و مرز تحویل

بستهٔ اصلی گردش مطالعه برای حالت powerplant پیاده‌سازی و محلی آزموده شد: قرارداد آرشیو، نگهداری انتخاب منبع، بازیابی با بازاعتبارسنجی، انتقال مستقل شواهد و گزارش منبع‌محور در پنج مسیر. این تحویل **ادعای تکمیل تمام قابلیت‌های نرم‌افزار یا انتشار مهندسی نیست**. on-grid/off-grid عملیاتی و dispatch متعلق به فاز ۴ هستند؛ baseline موجود آن‌ها به دادهٔ اختیاری پژوهش وابسته نشده است.

تحقیق فاز ۱ تا حد منابع در دسترس تکمیل شد: بستهٔ W/L، ۴۳ فایل pinned، ۲۰ ماتریس آزمایشگاهی و چهار مجموعهٔ هواشناسی، همراه پروتکل و ۸ آزمون. اصل اندازه‌گیری‌های DTU/SUPSI/SLTE و آزمون مستقل همهٔ زیرمدل‌ها همچنان باز هستند. این کمبودها مانع ادعای اعتبارسنجی مربوط‌اند، نه مانع استفاده از نرم‌افزار عمومی. منابع، نسخه‌ها، مجوزهای بررسی‌شده و محدودیت‌ها در `phase1/MULTICLIMATE-BENCHMARK.fa.md` و `phase1/RESEARCH-MODEL-DOSSIERS.fa.md` ثبت شده‌اند؛ دادهٔ هواشناسی TMY شاهد صحت تولید واقعی نیست.

## پیاده‌سازی

- `src/studies/operationalStudy.ts`: قرارداد `operational-study-v1` شامل شواهد کامل، context، پذیرش مسئول، descriptor و receipt؛ شناسه SHA-256 محتوایی؛ هر بازیابی دوباره از خروجی واقعی مدل عبور می‌کند، نه اعتماد به خلاصهٔ ذخیره‌شده. هیچ امضا یا اصالت خارجی از هش نتیجه نمی‌شود.
- descriptor اختیاری: ارتفاع با واحد متر، نام IANA منطقه زمانی، مدل ماژول/اینورتر، یادداشت و مرز اعلامی. این فیلدها صریحاً `user_declared_not_authenticated` هستند و **صرفاً annotation**؛ پارامترهای واقعی اجرای مدل از request داخل شواهد می‌آیند. تغییر annotation محاسبه را مخفیانه تغییر نمی‌دهد. تقویم پذیرش انرژی همچنان یک سال کامل UTC است، نه سال صورتحساب محلی با DST.
- IndexedDB مستقل `solarpv-operational-studies`: شواهد بزرگ وارد localStorage نمی‌شوند. پایان تراکنش شرط موفقیت ذخیره است؛ خطا/blocked/quota پنهان نمی‌شود. ذخیره به همین مرورگر و origin وابسته و قابل حذف است.
- `ProjectDataV3Schema` و مهاجرت: `operationalStudyId` اختیاری؛ پروژه‌های قدیمی به منبع پژوهشی نیاز ندارند. JSON پروژه فقط مرجع محلی را نگه می‌دارد. برای انتقال دستگاه، **JSON پروژه و آرشیو مستقل مطالعه را هر دو نگه دارید**؛ آرشیو به‌تنهایی تنظیمات پروژهٔ مقصد را تغییر نمی‌دهد و باید دقیقاً با context آن سازگار باشد.
- `OperationalEnergyPanel`: پذیرش صریح، ذخیره پیش از فعال‌سازی، دانلود/ورود آرشیو قابل‌انتقال، حدود اندازه، خطای قابل مشاهده، محافظ نسخه برای عملیات async و تغییر context. بدون داده‌سازی، extrapolation یا اعمال دوبارهٔ waterfall.
- `App`: snapshot مشترک save/export/report شناسه را حفظ می‌کند؛ restore همان پروژه حتی بعد از reload شواهد را بازاعتبارسنجی می‌کند. تغییر فیزیکی context منبع فعال را نامعتبر می‌کند. نبود یا خرابی شواهد پیام روشن و وضعیت screening دارد، نه ادعای ادامهٔ منبع قبلی. بازگشت صریح به screening مرجع انتخاب را پاک می‌کند.

### اشکال واقعی کشف‌شده در آزمون مرورگر

مهاجرت، provider claim واردشده را عمداً user-declared می‌کند. هش قبلی کل city را شامل provenance و سپس تمام خروجی‌های مشتق‌شده می‌کرد. قرارداد وابستگی اکنون فیلدهای فیزیکی city و توپولوژی رشته/ظرفیت را صریح برمی‌گزیند؛ گزارش منشأ همچنان حفظ و تنزل اصالت اجرا می‌شود. object قبل از stable hash از سریال‌سازی JSON عبور می‌کند تا کلید اختیاری `undefined` با نبود همان کلید پس از ذخیره تفاوت کاذب نسازد. هیچ hash mismatch پذیرفته یا از کنترل خارج نشده است. همچنین `tempAnnualMeanC` اختیاری که schema مهاجرت حذف می‌کرد، حفظ شد. تغییر مختصات همچنان منبع را غیرفعال می‌کند.

## گزارش منبع‌محور

دکمه‌های گزارش و Ctrl+E، وقتی منبع اجرایی فعال است، `OperationalReportModal` را باز می‌کنند. این یک dossier محدود به انرژی/مالی و هویت شواهد است، نه بازنویسی تمام گزارش EPC:

1. سند چاپ با امکان Save as PDF مرورگر؛
2. HTML مستقل با escape متن کاربر؛
3. Word واقعی OOXML؛
4. Excel واقعی OOXML با sheet منبع/خلاصه و cashflow؛
5. JSON شامل snapshot ورودی پروژه، receipt، مالی و **تمام آرشیو شواهد**.

تولید/خرید انرژی، سال، ظرفیت‌ها، مختصات، مرز AC، پذیرش، هش، LCOE/IRR/NPV و cashflow مدل‌شده از منبع فعال می‌آیند. PR، waterfall و منحنی روز نمایندهٔ screening عمداً حذف‌اند؛ ترکیب این نمودارها با درآمد منبع دیگر مجاز نیست. گزارش EPC قبلی فقط برای screening باقی است. تغییر منبع، گزارش باز را می‌بندد؛ متن arbitrary کاربر وارد HTML اجرایی نمی‌شود.

**مرز مهم:** خروجی اینورتر الزاماً کنتور فروش نیست. هیچ تلفات کارخانهٔ مدل‌نشده‌ای خودکار فرض/کسر نشده و هیچ تأیید استاندارد/ساخت/بانک‌پذیری صادر نمی‌شود. اگر گزارش EPC یکپارچه با همهٔ صفحات سازه/برق و منبع اجرایی لازم باشد، آن توسعه و بازبینی صفحات هنوز باقی است؛ مسیر حاضر dossier منبع‌محور مستقل است.

## آزمون‌های اجراشده

- `npm run lint:types`: client و node، PASS.
- `npm run build`: PASS؛ هشدارهای chunk بزرگ، import پویا/ایستا و annotation وابستگی zod باقی‌اند.
- `npm run test:all`: benchmark و audit، PASS؛ شامل گیت شواهد مستقل فیزیک. این نتیجه آزمون نرم‌افزاری است، نه اعتبارسنجی میدانی.
- `PVLIB_PYTHON=.cache/thermal-research/venv/bin/python npm run test:operational:energy`: PASS؛ سال کامل direct و integrated واقعیِ worker با ورودی **مصنوعی مخصوص آزمون**، رد دوره ناقص/همپوشانی/سایت/ظرفیت، مالی خرید برق.
- `npm run test:operational:study`: PASS؛ roundtrip JSON، بازمحاسبه receipt، خرابکاری descriptor/context/receipt/evidence/id، metadata اختیاری و schema مرجع.
- `PVLIB_PYTHON=.cache/thermal-research/venv/bin/python npm run test:operational:browser`: PASS؛ برنامهٔ production در Chromium، دانلود context، پذیرش سالانه، آرشیو، reload و restore پروژه، مالی واقعی، چهار فایل دانلودی و readback، امضای ZIP در OOXML، سند popup چاپ و درخواست print، پاک‌شدن شواهد محلی/خطای روشن/بازیابی با آرشیو، بازگشت screening و invalidation با تغییر سایت. خود موتور خروجی PDF سیستم‌عامل تست نشده؛ درخواست چاپ و محتوای سند آزموده شده‌اند.
- `PVLIB_PYTHON=.cache/thermal-research/venv/bin/python npm run test:study:workflow`: PASS؛ کل زنجیره، شامل ماتریس ۸۱۹۲ قرارداد و ۱۶ نتیجه runtime. اجرای اولیه بدون متغیر Python مناسب شکست خورد؛ پس از تعیین محیط دارای pvlib، تمام زنجیره عبور کرد.
- `npm run verify:exports`: PASS، readback گزارش قدیمی DOCX/XLSX/JSON و re-import.
- `.cache/thermal-research/venv/bin/python docs/research/phase1/test-benchmark-package.py`: ۸/۸ PASS.
- `git diff --check`: PASS.

فرمان‌های Python به محیط نصب‌شده با pvlib 0.13.1 نیاز دارند؛ cache بخشی از محصول/تضمین نگهداری نیست. fixture آزمون سالانه با `test:operational:energy` تولید می‌شود؛ دادهٔ عملیاتی کاربر نیست.

## محدودیت‌ها و ادامهٔ لازم

- آزمون جاری Chromium/Linux است؛ Windows، Safari، محدودیت quota واقعی، PDF renderer و CI روی commit دقیق در این تحویل اجرا نشده‌اند.
- snapshot پروژه و مطالعه مستقل‌اند؛ پشتیبان یک‌فایلی از کل پروژه+همه مطالعات، فهرست/حذف مدیریتی مطالعات اجرایی و همگام‌سازی حساب/ابر پیاده نشده‌اند.
- descriptor جای احراز اصالت datasheet، کالیبراسیون حسگر یا نگاشت کنتور نیست. قراردادهای request موجود همچنان مرجع پارامتر اجرایی‌اند.
- تکمیل گزارش EPC جامعِ غیرمختلط، با تمام صفحات قبلی و همین منبع، باقی است؛ به همین دلیل «تمام فاز ۲ بدون باقی‌مانده» ادعا نمی‌شود.
- تغییرات قبلی workspace حفظ شده‌اند؛ commit/push/merge انجام نشده. HEAD پایه همچنان `5438fb59f4bb5cde05c20818b780464e1fe28752` و شاخه `arena/237e6ea2-solarpv-studio` است؛ آزمون‌ها روی working tree محلی‌اند، نه CI همین SHA.
