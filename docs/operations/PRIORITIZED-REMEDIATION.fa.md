# برنامهٔ دو فازی اصلاح ایرادهای تأییدشده

این برنامه برای کد اجرایی شاخهٔ فعلی است؛ بسته‌شدن همهٔ یافته‌ها یا انطباق مهندسی کل محصول را ادعا نمی‌کند. اصلاح قبلی خورشید و حذف مسیر AC دوباره به‌عنوان کار جدید شمرده نمی‌شوند.

## فاز ۱: حفاظت اطلاعات و موانع انتشار/جانمایی

| ترتیب | کار | معیار پذیرش | وضعیت |
|---|---|---|---|
| ۱ | جداسازی فایل ناموجود از بازیابی شکست‌خورده | بایت‌های اصل پس از import، ذخیره مستقیم و SIGINT/SIGTERM عیناً حفظ شوند؛ seed و import نیمه‌کاره ممنوع | پیاده‌سازی و آزمون محلی موفق |
| ۲ | بستهٔ مستقل Docker | ایمیج تازه، بدون bind mount سورس، با تنظیم auth و پاسخ ۲۰۰ healthy از `/api/health` | Dockerfile و گیت واقعی CI اصلاح شد؛ اجرای واقعی این محیط به‌علت نبود Docker تأیید نشده |
| ۳ | قیود هندسی CAD پیش از شمارش ظرفیت | هر میز داخل مرز قابل ساخت، بیرون جاده و تمام تجهیزات؛ ظرفیت از مجموعهٔ معتبر؛ زمین غیرقابل‌جانمایی صفر میز | برنامه‌ریزی‌شده؛ هنوز تغییر نکرده |

### رفتار بازیابی
- JSON معیوب، schema پشتیبانی‌نشده، tuple نامعتبر، خطای I/O و symlink آویزان، فایل جدید محسوب نمی‌شوند.
- مسیر شکست‌خورده تا پایان همان فرایند در latch فقط‌خواندنی می‌ماند؛ تغییر مسیر آزمایشی به همان مسیر latch را پاک نمی‌کند.
- snapshot در نمونه‌ای جدا اعتبارسنجی می‌شود؛ دادهٔ ناقص وارد پایگاه فعال نمی‌شود.
- `saveDatabase` در وضعیت مسدود false برمی‌گرداند؛ handlerهای خروج نیز از همین تابع استفاده می‌کنند.
- سلامت در این وضعیت HTTP 503، `degraded / recovery_blocked` است. این ادعای read-only بودن تمام محاسبات حافظه نیست؛ ذخیره روی مسیر معیوب ممنوع است.
- فقط نبود واقعی فایل اجازهٔ ایجاد seed تازه می‌دهد. snapshot معتبر خالی معتبر باقی می‌ماند و با نمونه پر نمی‌شود.

### راهنمای بازیابی اپراتور
۱. اگر health وضعیت recovery_blocked داد، درخواست‌های نوشتنی را متوقف و فرایند را خاموش کنید؛ خروج نیز فایل معیوب را تغییر نمی‌دهد.
۲. **ابتدا** فایل اصلی را در مسیر امن نسخه‌برداری و checksum کنید. محتوای حساس را در log یا Git قرار ندهید.
۳. نسخهٔ پشتیبان مستقل و بررسی‌شده را به مسیر بازیابی‌شده برگردانید، یا پس از نگه‌داشتن اصل، `SOLARPV_DB_FILE` را به مسیر تازه تغییر دهید.
۴. فرایند را دوباره اجرا و health و پروژه‌ها را کنترل کنید. هیچ دکمه/flag دورزدن خودکار latch وجود ندارد.

### Docker
- builder و runner از Node 22.22.3-alpine استفاده می‌کنند، همسو با engines فعلی.
- `tsx` از lockfile و وابستگی production نصب می‌شود؛ نصب global شناور حذف شد.
- درخت کامل `src` و فایل‌های worker در `services` کپی می‌شوند، نه صرفاً engine. importهای router، studies و capabilities باید موجود باشند.
- `npm run test:container` واقعاً build/run/health را اجرا می‌کند؛ نبود Docker نتیجهٔ موفق/skip سبز نیست.
- این smoke گواهی نصب Python و کتابخانه‌های علمی نیست؛ runtime علمی اختیاری باید جداگانه نصب و آزموده شود. auth تولیدی همچنان لازم است.

## فاز ۲: محاسبات و قراردادهای خروجی/لغو

ترتیب زیر پس از قیود CAD دنبال می‌شود؛ موارد جدول هنوز پیاده‌سازی نشده‌اند:

۱. **POA:** یک قرارداد پیش‌فرض ثابت و اعلام‌شده، حذف تشخیص قرارداد از برابری عددی زاویه؛ آزمون HTTP پیوستگی اطراف ۱۸۰ درجه و هر دو قرارداد صریح.
۲. **Worker سایه:** دو درخواست هم‌زمان و لغو یکی؛ هر دو حتماً resolve یا reject شوند. خطا و توقف worker همهٔ کارهای متأثر را تعیین‌تکلیف کنند. fallback باید زمان اجرا را به حلقهٔ رویداد پس بدهد و لغوپذیری واقعی داشته باشد؛ Promise به‌تنهایی offloading نیست.
۳. **دوطرفه:** صفرشدن مؤلفه مستقیم با DNI=0 و AOI واقعی پشت؛ sky-view پشت صفحه افقی رو به زمین صفر؛ sliceCount صحیح، محدود و متناهی؛ diagnostics شامل سقف فعال و مازاد واقعی حذف‌شده. اصلاح این موارد گواهی کل مدل heuristic نیست.
۴. **ردیاب:** سهم سایه با هندسه و fixture مستقل pvlib؛ لحاظ محدودیت مکانیکی و backtracking. افت انرژی از میانگین سادهٔ سطح سایه به‌دست نمی‌آید و باید جدا بررسی شود.
۵. **سوخت:** حفظ دقت تا پس از ضرب در ساعت/ذخیره؛ بار مثبت و زمان مثبت مخزن صفر ناشی از rounding ندهند. این اصلاح دقت تجربی منحنی سوخت را ثابت نمی‌کند.
۶. **بار صفر:** تفکیک صفر معتبر از ورودی ناموجود؛ آزمون پیوستگی و حالت‌های بار صفر/کم/نامعتبر بدون تغییر ناخواستهٔ مرز مالی.

## سه بازبینی و بررسی تکمیلی
۱. مسیر خواندن، import نیمه‌کاره و seed بررسی شد؛ پس از آن آزمایش فرایند جدا برای فایل معیوب/ناموجود/خالی و حفظ بایت‌ها انجام شد.
۲. تمام فراخوانی‌های save و handlerهای خروج بررسی شد؛ پس از آن آزمایش SIGINT، SIGTERM، ذخیره مستقیم، directory I/O error و symlink آویزان انجام شد.
۳. importهای مستقیم سرور و درخت router/study بررسی شد؛ پس از آن گیت ایمیج واقعی مستقل به CI اضافه شد. نبود Docker محلی به‌عنوان فقدان مدرک ثبت است، نه تأیید انتشار. این بررسی‌ها پژوهش کد/قراردادند، نه پژوهش تجربی مستقل یا گواهی محاسبات مهندسی.

## Rollback و توقف ایمن
برای حفاظت داده bypass ناامن وجود ندارد. پیش از rollback اصلاح بازیابی، سرور نوشتنی را متوقف کنید و اصل snapshotها را نگه دارید؛ مسیر معیوب نباید دوباره seed شود. گیت Docker باید تا اجرای واقعی سبز نشده «مانع انتشار» بماند. حذف‌ها از تاریخچه Git قابل بازیابی‌اند؛ پاک‌سازی به فایل‌های تغییرکردهٔ قبلی کاربر یا کد آزمون‌های فعال دست نزده است.

## اصلاحات باقیمانده — ۲۰۲۶-۱۱-۰۳

### قرارداد و معیار پذیرش
- POA: پیش‌فرض قدیمی همواره `south_zero` است؛ برای دادهٔ شمال‌مبنا `surfaceAzimuthConvention: north_clockwise` ارسال کنید. تغییر قرارداد ناشناخته خطای ۴۰۰ دارد؛ عبور خورشید از ۱۸۰ درجه نباید قرارداد را تغییر دهد.
- سایهٔ سالانه: دو کار هم‌زمان مستقل؛ لغو یکی نباید دیگری را متوقف کند. ظرفیت بیش از دو کار صریحاً رد می‌شود. در نبود Worker، اجرا با برش زمانی و لغو تعاونی انجام می‌شود. این fallback تضمین اجرای Python/server نیست و برای تحلیل سنگین گیت محاسبات سرور همچنان لازم است.
- CAD: تمام footprint پنل‌ها باید در محدوده و بیرون کریدور/ایستگاه باشند؛ شمارش و ظرفیت از میزهای واقعاً پذیرفته‌شده محاسبه شود؛ زمین کوچک می‌تواند صفر میز داشته باشد.
- دوطرفه: rear beam با نرمال معکوس؛ sky-view افقی پشت صفر؛ slices صحیح در بازهٔ ۴ تا ۲۵۶. cap فعال ۱۵/۲۵ درصد و excess نسبت به همان cap گزارش می‌شود.
- tracker: سایه با هندسهٔ Eq12 و وزن‌دهی انرژی پرتو، نه میانگین ساده. سوخت پیش از جمع‌زدن گرد نمی‌شود؛ بار صفر صفر می‌ماند و ورودی منفی/نامتناهی رد می‌شود.

### مدرک و محدودیت
`npm run test:remaining` چهار آزمون عددی/چرخه‌عمر/HTTP/Chromium را اجرا می‌کند. fixture مستقل از pvlib نسخهٔ 0.13.1 با `scripts/fixtures/generate-remaining-geometry.py` تولید شده: ۱۲۶۰ حالت tracker (بیشینه خطای fraction برابر 2.665e-15)، ۱۲۸ حالت rear direct و ۲۷ جانمایی. اینها تأیید مؤلفهٔ هندسی‌اند، نه دقت سالانه/میدانی یا استاندارد اجرایی. تست مرورگر Worker از Vite module harness استفاده می‌کند، نه بستهٔ production.

هدف قدیمی bifacial برابر ۱۰٫۴۰ درصد فاقد اجرای مستقل قابل‌بازتولید SAM است. خروجی فعلی حدود ۹٫۲۲ و اختلاف ۱۱٫۳۵ درصد **حذف یا با کالیبراسیون پنهان نشده**؛ مقایسه با برچسب `retired_unverified_target` و WARN باقی می‌ماند. تغییر آن از FAIL عددی به WARN تصمیم صریح بازنشستگی مرجع نامعتبر است، نه تأیید فیزیکی. گزارش کلی نیز WARN است. گیت مستقل کل مدل همچنان BLOCKED است.

سه بازبینی تکمیلی: (۱) قرارداد زاویه/مرز Worker و سپس آزمون HTTP واقعی و Chromium؛ (۲) هندسهٔ rear/tracker و سپس مطالعهٔ پیاده‌سازی مستقل pvlib و تولید fixture جدا از TypeScript؛ (۳) footprint/count و گردکردن سوخت و سپس آزمون ۲۷ جانمایی و بار کم/صفر. اینها پژوهش کد/منبع‌اند و جای پژوهش میدانی را نمی‌گیرند.

### استفاده، rollback و مرز مالی
نتایج Research هنوز بدون پوشش زمانی/تطبیق پروژه/گیت ثبت‌شده وارد انرژی سالانه یا مالی نمی‌شوند. اصلاحات هندسی مدل معمولی می‌توانند بر خروجی معمولی اثر بگذارند؛ این اثر، مجوز ورود Research به مالی نیست. flag مستقل برای احیای الگوریتم معیوب اضافه نشده است: rollback باید به‌صورت patch معکوس انتخابی همراه با fixture/قرارداد و اجرای مجدد آزمون‌ها باشد، نه reset کل کارهای موجود. برای توقف امن تحلیل سایه از AbortSignal استفاده کنید؛ خرابی Worker محاسبه را مخفیانه موفق اعلام نمی‌کند. Docker و گیت مستقل هشت مدل تا ارائهٔ مدرک واقعی مانع انتشار باقی می‌مانند.
