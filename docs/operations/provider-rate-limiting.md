# Provider request coordination

All outbound data-provider HTTP calls (PVGIS, NASA POWER, ISRIC SoilGrids, Nominatim, and Overpass) must use `fetchProvider` from `src/engine/dataGateway/providerRequestLimiter.ts`. The gate is shared between provider instances in one JS process, caps total active upstream requests at four, preserves aborts, and applies minimum per-provider spacing (100 ms; Nominatim 1,050 ms). Do not add direct `fetch()` calls to provider adapters.

## More than one server instance

The in-memory gate is intentionally process-local. For a horizontally scaled deployment:

1. Set `APP_INSTANCE_COUNT` to the actual number of gateway server processes/replicas.
2. Configure a Redis REST endpoint and bearer token via `PROVIDER_LIMITER_REDIS_REST_URL` and `PROVIDER_LIMITER_REDIS_REST_TOKEN` on every replica. Redis `EVAL` atomically reserves shared provider time slots; the Nominatim key is common to reverse and forward geocoding.
3. The server refuses startup when `APP_INSTANCE_COUNT > 1` but those Redis settings are absent. Keep the count accurate; autoscaling systems must set it to the configured maximum or use a single dedicated provider-gateway service.

In development a single process can use the in-memory gate without Redis. **In production, Nominatim is disabled unless the shared Redis REST coordinator is configured**, even for a single instance. Geocoding returns a service error rather than an empty successful result when the coordinator is unavailable. Never place the Redis token in Vite/client environment variables. Browser requests use the same-origin gateway only; if it is unavailable, they remain on the local analytical model rather than bypassing the server limiter with direct provider calls.

A successful claim reply is bounded by a 10-second coordinator timeout and checked against the lease's conservative remaining lifetime before an upstream invocation; late replies fail closed. An uncertain claim can hold the lease until expiry, affecting availability. Upstream rejections are observed immediately while the post-invocation release is pending; release failures are logged and never automatically retry a possibly-started request. The release timestamp spaces the next claim after a confirmed invocation. These are bounded-delay protections, **not a mathematical guarantee against an arbitrary process/host pause between the final local lease check and starting the upstream request**. A production environment that requires a hard spacing guarantee under arbitrary pauses needs a dedicated single egress service or upstream-enforced fencing/rate limiting. The local Redis tests use a disposable Redis server and synthetic REST/upstream adapters, not production Redis REST or live providers.

## Cache and fallback policy

Climate remote results use the climate provider's configured remote TTL; analytical fallback has its shorter TTL. Soil remote results use the soil provider's remote TTL; analytical fallback has its short TTL. Structural hazard inputs are generated by a deterministic local screening model and are not represented as live provider data. Cache hits are still rejected when the requested policy disallows their source class. Caller aborts do not become cache entries, analytical fallbacks, or circuit-breaker failures.
