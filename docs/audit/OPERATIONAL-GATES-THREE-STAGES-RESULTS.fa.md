## مرحلهٔ ۱ — مرجع مالی مستقل و حساسیت فرمول

هفت گرهٔ مالی قبلاً بدون fixture بودند. اکنون برای هر هفت گره فایل مستقل، binding مستقیم export و witness حساسیت دقیق AST داریم:

- `performFinancialAnalysis`: هزینهٔ خرید برق، fallback نبود import، OPEX سال‌های بعد، هزینهٔ سالانه‌شده.
- `sanitizeFinancialPricing`: مقدار نامعتبر، زیر حداقل و بالاتر از سقف؛ سه literal در موقعیت واقعی خود با ورودی‌ای آزموده می‌شوند که آن حد واقعاً در خروجی اثر داشته باشد.

Generator مستقل `scripts/fixtures/physics/generate-grid-import-ledger.py` فقط از stdlib/Python Decimal استفاده می‌کند؛ TypeScript، اجرای production و خروجی محاسباتی آن را نمی‌خواند. تمام کلیدهای خروجی با fixture مقایسه می‌شوند. متن metadata صرفاً قرارداد گزارش است؛ پارامترهای آزمون انتخاب صریح‌اند، نه قیمت‌های پیشنهادی SSC یا دادهٔ سایت.

شواهد عددی مستقل:

- حالت بدون سرمایه: خرید 100kWh × تعرفه 2 = هزینهٔ سال اول 200؛ رشد 10٪ → سال دوم 220؛ NPV با discount صفر = −420؛ انرژی دو سال 200kWh، LCOE=2.1، proxy سال اول=2.
- حالت سرمایه و هزینهٔ ثابت غیرصفر: سرمایه 1000، OPEX پایه 100/200، هزینهٔ ثابت 30، خرید 200/220 → جریان‌های هزینه 330/450؛ NPV=−1780، LCOE=8.9 و proxy سالانه‌شده=8.3. این ورودی‌ها mutationهای مؤلفه‌های غیرصفر را آشکار می‌کنند؛ ورودی صفر که mutation را پنهان می‌کرد، قبول نشد.
- حالت نبود customPricing: ledger مستقل با سیاست‌های پیش‌فرض صریح برنامه، خرید صفر، درآمد سالانه و discount مشخص. هیچ ادعایی دربارهٔ صحت فیزیکی پیش‌فرض‌ها یا برابری کل موتور با SAM ندارد.

### حفظ سخت‌گیری گیت

JSON مقدار JavaScript `undefined` را ذاتاً نمایش نمی‌دهد، درحالی‌که خروجی مالی چنین کلیدهایی دارد. قالب opt-in `expectedEncoding: js-undefined-v1` با marker دقیق `{$undefined:true}` افزوده شد. هیچ کلیدی حذف یا نادیده گرفته نمی‌شود؛ decoder فقط همان marker دقیق را به undefined تبدیل می‌کند و مقایسهٔ کلیدها، نوع، اعداد و tolerance قبلی بدون تغییر باقی مانده است. تست‌ها missing-key، null، صفر، عدد دستکاری‌شده و marker دارای کلید اضافی/مقدار غلط را رد می‌کنند. fixtureهای قدیمی بدون opt-in همان semantics قبلی را دارند.

هیچ formula hash مستثنا نشد، هیچ literal ماسک نشد، gate خاموش نشد و مسیر sensitivity تغییر نکرد. `--check` targets را بدون بازنویسی با generator بازتولید و مقایسه می‌کند و در فرمان `verify:physics-reference-gate`/CI موجود اجرا می‌شود. گیت برای هر هفت گره PASS شد.

## مرحلهٔ ۲ — گیت‌های اجرایی و رفتار واقعی رابط

- پذیرش batch اکنون علاوه بر تنظیمات فیزیکی، engine version، مدل‌ها، وابستگی‌ها و hashهای worker/requirements در direct و integrated/child را مقایسه می‌کند؛ مخلوط‌کردن نسخه‌ها رد می‌شود. این مقایسه اصالت امضاشدهٔ hash یا کالیبراسیون پارامترها را اثبات نمی‌کند.
- بودجهٔ 64MiB علاوه بر file input رابط، در adapter نیز اعمال می‌شود؛ فراخوان مستقیم adapter نمی‌تواند آن را دور بزند.
- همهٔ entry pointهای درخواست گزارش رسمی، از جمله Ctrl+E، به یک گیت واحد متصل شدند. گزارش screening/مالی اجرایی مخلوط صادر نمی‌شود؛ درخواست مسدودشده پس از بازگشت به screening در صف نمی‌ماند.
- race ورود فایل هنگام تغییر context/unmount با token نسخه و cleanup حل شد، بدون غیرفعال‌کردن قانون lint.
- آزمون واقعی worker برای سال عادی 8760 و سال کبیسه 8784 انجام می‌شود. داده‌ها **clear-sky مصنوعی برچسب‌دار فقط برای آزمون** هستند؛ دادهٔ عملیاتی ساخته/پر نشده است.
- آزمون واقعی Chromium روی App: context download، import، پذیرش، عدد واقعی FinancialTab، مسدودبودن گزارش با میان‌بر، reset و ابطال با تغییر سایت.

### ایراد اجرایی کشف‌شده و اصلاح آن

اضافه‌شدن آزمون حجیم سال کبیسه، timeout ورودی worker در اجرای batch را بازتولید کرد: `communicate` با stdin pipe و polling کوتاه، پس از timeout نوشتن گاهی کودک را منتظر EOF نگه می‌داشت. worker API تولید انرژی تغییری نکرد؛ در helper ترکیب، stdin هم مانند stdout/stderr disk-backed شد. canonical request یک بار در فایل موقت محدود نوشته و seek می‌شود؛ فرایند با wait bounded پایش و هنگام cancel/timeout خاتمه می‌یابد.

Regression اختصاصی transport، ورودی 2MiB و خوانندهٔ عمداً کند با نیاز به EOF را می‌سنجد؛ این fixture transport-only است و به‌عنوان شاهد فیزیک جا زده نمی‌شود. سپس همهٔ تست‌های پژوهشی و اجرای واقعی سالانه موفق شدند؛ timeout بودجه را صرفاً بزرگ‌تر نکردیم.

## وضعیت انتشار و محدودیت‌های صریح

- این کار گیت نرم‌افزاری/عددی محلی را رفع می‌کند؛ نه تأیید میدانی یا بانکی.
- اتصال اجرایی هنوز opt-in، memory-only و فقط powerplant است. persistence خودکار انتخاب و گزارش رسمی چندمنبعی فعال نشده‌اند؛ این مسیرها fail-closed باقی می‌مانند، نه این‌که کامل اعلام شوند.
- تطبیق تفصیلی سازنده/پارامترهای ماژول، altitude/timezone و مرز فیزیکی محل فروش همچنان نیاز به بررسی مهندسی دارد؛ این نسخه فقط مطابق قرارداد موجود سایت lat/lon، ظرفیت، context و تنظیمات batch را gate می‌کند.
- دما/توان لحظه‌ای مدل‌های advanced خودکار به kWh/درآمد سالانه تبدیل نمی‌شوند. اتصال temporal/optical/electrical سازگار آن‌ها همچنان کار جداست؛ خروجی غیرانرژی برای مالی رد می‌شود.
- Windows و CI راه‌دورِ SHA دقیق در این محیط اجرا نشده‌اند. YAML به معنی PASS نیست. داده و تأیید مستقل پروژه موجود نیست؛ برچسب `not_field_validated` حفظ شده است.
- کارهای قبلی حفظ شده‌اند؛ هیچ stage/commit/push/merge انجام نشده است. برای Push، بازبینی انتخابی مجموعهٔ تغییرات، بررسی اسرار و commit منتخب روی همین شاخه لازم است؛ هیچ push به main یا تغییر تاریخچه مجاز نشده است.
