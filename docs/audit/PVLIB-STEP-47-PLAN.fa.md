موجودی: field_evidence در runStudyValidation دارای refs/criteria، optional calibration با test مستقل، gateهای synthetic/quality/receipt/energized/period و status اعلامی است؛ نمایش فقط JSON عمومی دارد. این مرحله نمای dossier، جدول actual/threshold/unit/pass، coverage/status/rows و export مستقل را اضافه می‌کند؛ هسته و قرارداد report/protocol۴۴ ثابت می‌مانند.

ضمیمهٔ اختیاری document register با schema/version، studyInputSha256 و planSha256 و datasetId به plan قفل می‌شود. هر سند category/reference (مطابق reference همان plan)، SHA256 اعلامی محتوا، reviewedBy/reviewedAt و applicabilityStart/End صریح دارد. حداکثر۱سند در هر یک از۴category، سقف۶۴۰۰۰بایت؛ اسناد ناقص/نامعتبر/بیرون پنجره با error یا readiness غیرکامل شفاف‌اند، نه اعتبارسنجی خودکار سند. غیابregister مجاز ولی readiness=references_only است. رجیستر فقط metadata است، نه مدرک اصلی یا signature؛ purpose/quality/receipt gateهای اصلی هرگز دور زده نمی‌شوند. window همهٔ مدارک باید **کل span بازه‌های استفاده‌شده** را بپوشاند، نه صرفاً labelmidpoint؛ برای calibration، sensor/time/site مدارک train+test و independentReview حداقل evaluation را پوشش دهند.

خروجی study-field-evidence-review-v1 شامل fingerprint دقیق result و report قدیمی، criteria table، evaluation raw/evaluated summary و rows (فقط paired پیش‌بینی)، register/hash/checks و dossierStatus. core blocked همیشه blocked؛ core criteria fail همانfail؛ core criteria met بدونregisterکامل => evidence_review_required؛ core met +registerکامل => declared_dossier_complete، همچنان not_field_validated و بدون استاندارد/گواهی. raw و adjusted در صورت calibration جدا هستند؛ انرژی فقط جفت‌های توان، دما انرژی ندارد، اصلاحclipنمی‌شود.

UI فقط پس از field_evidence موفق (حتی blocked report) نمای اختصاصی، دلایل، refs، جدولmetric/gate وcoverage می‌دهد؛ registerJSONاختیاری به تأیید صریح نیاز دارد؛ JSON/CSVمعیارها/CSVردیف‌ها/HTML قابل دریافت و edit/reset/recompute بدون تغییر مدل یا مالی. فایل register جدا برایبازتولید و SHA آن در dossier؛ report/protocol قدیمی register را شامل نمی‌شود.
