Gate با TypeScript AST diff مبنا تا HEAD را می‌سنجد؛ operatorهای حسابی و compound assignmentها (`+=`, `-=`, `*=`, `/=`, shifts و bitwise)، همچنین `++`/`--`، آستانه‌های عددی و call siteهای helperهای محاسباتی نام‌گذاری‌شده را به‌عنوان واحدهای محاسباتی ردیابی می‌کند. آزمون منفی ثابت می‌کند که تغییر `sum += x` به `sum -= x` و `sum++` به `sum--` fixture obligation می‌سازد. برای هر formula ID، manifest به‌جای اعتماد به متن تست دلخواه، مسیر fixture، نام export تابع production، آرگومان‌های ورودی، خروجی مستقل مورد انتظار، tolerance عددی، و منبع HTTPS با edition/locator می‌خواهد. Gate شناسه را با مسیر lexical مالک می‌سازد، نه فقط نام برگ تابع؛ بنابراین nested function/class method هم‌نام قابل اشتباه‌گرفتن با تابع بالادستی نیست. برای اجرای fixture، در حال حاضر فقط ownerای پذیرفته می‌شود که خودش یک named export مستقیم در همان فایل باشد: نام export باید دقیقاً با owner path برابر شود و AST همان گره/occurrence مشخص را داخل بدنهٔ مالک مستقیم بیابد. اجرای fixture روی نسخهٔ موقتِ instrument‌شدهٔ همان منبع انجام می‌شود؛ hook هنگام ارزیابی همان AST node ثبت می‌کند. برای operator nodeها، probe عملگر همان occurrence را به عملگر متقابل تغییر می‌دهد (از جمله compound assignment و ++/--) تا اثرات جانبی حفظ‌شده نیز واقعاً تغییر کنند؛ برای nodeهای دیگر مقدار نتیجهٔ همان occurrence را perturb می‌کند. اجرای baseline باید خروجی مستقل fixture را با tolerance برآورده کند، و اجرای probe با همان ورودی‌ها باید خروجی تابع را تغییر دهد. بنابراین گرهٔ انتخاب‌شده باید در ورودی fixture اجرا شود و در آن مسیر بر خروجی اثر بگذارد؛ تست policy مورد mismatch، owner/export نادرست، branch اجرا‌نشده، occurrence تکراریِ بدون اثر و عبارت اجراشده اما بی‌اثر بر خروجی را رد می‌کند. بدنه‌های private/helper و class method هنوز adapter call-path ندارند و برای آن‌ها gate fail-closed است. این probe شاهد اثرگذاری در همان ورودی/مسیر است، نه اثبات جامع data-flow برای همهٔ مسیرها یا صحت علمی مرجع. این تغییر قدرت کنترل را بالا می‌برد اما AST detector هنوز یک screening مکانیکی است، نه اثبات پوشش کامل همهٔ الگوهای محاسباتی، و metadata/پرچم استقلال، مجوز یا صحت منبع را به‌طور خودکار تأیید نمی‌کند؛ بازبینی منبع و روش لازم است. `scripts/physics-reference-evidence.json` اکنون سه fixture مستقل دارد: (۱) ضریب تجمیعی derate طبق PVWatts V5، معادلهٔ (9) بخش System Losses؛ با هفت retained factor، حاصل مستقل `0.734061533184` و گردکردن قراردادی به `0.734062`. این مرجع فقط ضربِ کسریِ lossهای داده‌شده را می‌آزماید و صحت تجربی ورودی‌های loss را تأیید نمی‌کند. (۲) افت ولتاژ DC دو سیمه در `calculateVoltageDropDc` با فرمول مستقل مقاومت/قانون اهم و ضریب طول رفت‌وبرگشت ۲، با مقاومت ویژهٔ مس در 20°C؛ ورودی SI مستقل `[6 m, 15 A, 10 mm², 24 V, 0.017241 Ω·mm²/m]`، افت حلقه `0.310338 V` و خروجی `1.293075%` است. منبع محاسباتی مستقل PDHonline, *Voltage Drop Calculations* (2026), Common Formulas, single-phase approximate Eq. 2 است؛ مقدار مقاومت ویژه جداگانه در Copper Development Association, *Introduction to Copper*, Table 5 ثبت شده است. fixture محدودیت‌های ساده‌سازی مقاومت ثابت 20°C را برطرف نمی‌کند و پارامتر پیش‌فرض production `rho=0.0175` را مستقلاً ارزیابی نمی‌کند. ## مواردی که عمداً بسته‌شده اعلام نمی‌شوند

1. **Sign-off و شواهد مهندسی بیرونی:** PE/مهندس حفاظت و ارتینگ/سازه/ژئوتکنیک/اتصال شبکه/مالی، دادهٔ معتبر site-specific، خاک/بورهول/pullout، study fileهای مستقل SAM/PVsyst/ETAP/DIgSILENT و مجوز استفاده از آن‌ها در دسترس نیست. این موارد با کدنویسی یا جست‌وجوی وب قابل جعل یا جایگزینی نیستند؛ باید توسط مالک پروژه و افراد دارای صلاحیت فراهم شوند.
2. **دقت فیزیکی و standards compliance:** تغییرات UI صرفاً از اعتماد کاذب جلوگیری می‌کنند؛ مدل‌های earthing، harmonic/PCC، سازه، انرژی و مالی همچنان screening هستند. ادعای IEC/IEEE/ASCE/NEC compliance یا bankability صادر نمی‌شود.
3. **Security production review:** JWT issuer/audience باید با IdP واقعی verify شود؛ rate limit فعلی per-process است؛ penetration test، authorization matrix کامل، abuse-cost caps، secrets manager، CORS policy/production headers، trusted proxy config و datastore چندنمونه‌ای مستقل ارزیابی نشده‌اند.
4. **Performance/accessibility:** cold-load/route profile و معیارهای UX ازپیش‌تعریف‌شده، split/lazy loading بر مبنای trace، WCAG keyboard/screen-reader/contrast/reduced-motion audit کامل انجام نشده‌اند. حجم chunk یا lint warnings به‌تنهایی با این patch حل نمی‌شوند.
5. **CI required enforcement (مسدود به‌علت دسترسی):** ruleset با status check موردنظر فعال است، اما target include خالی است و API برای branch `main` هیچ rule مؤثری برنمی‌گرداند. PUT اصلاح target با 403 رد شد؛ تا ثبت صریح `refs/heads/main` و بازگشت check از endpoint قواعد شاخه، الزام روی main حل‌شده نیست.
6. **آزمون‌های موجود، ارزیابی بیرونی نیستند:** اجرای موفق benchmark یا قراردادهای policy نباید به‌عنوان تأیید صحت مهندسی/علمی تعبیر شود.

## منابع بررسی‌شده

- IETF, [RFC 8725 — JSON Web Token Best Current Practices](https://www.rfc-editor.org/rfc/rfc8725.html): الگوریتم/اعتبارسنجی claims و ضرورت اعتبارسنجی audience در صورت کاربرد چند relying party؛ خود RFC تعیین‌کنندهٔ issuer/audience خاص این محصول نیست.
- OWASP, [API4:2023 — Unrestricted Resource Consumption](https://owasp.org/API-Security/editions/2023/en/0xa4-unrestricted-resource-consumption/): لزوم محدودسازی نرخ، تعداد/اندازهٔ درخواست و هزینهٔ عملیات؛ محدودیت in-memory فعلی تنها یک لایه است.
- NREL, [PVWatts Version 5 Manual](https://pvwatts.nrel.gov/downloads/pvwattsv5.pdf), Aron P. Dobos, 2014-09-04, §11 Eq. (9): قاعدهٔ aggregate loss ضرب کسرهای باقیمانده؛ تنها همین رابطه برای fixture `calculateStandardDeratingFactor` مبناست، نه مقادیر empirical هر loss.
- David A. Snyder, PE, [Voltage Drop Calculations](https://pdhonline.com/courses/e426/e426content.pdf), PDHonline Course E426 (2026), Common Formulas, Single-Phase Approximate Eq. 2: افت دو سیمه در طول رفت‌وبرگشت و رابطهٔ مقاومت/جریان؛ برای fixture DC کابل.
- Copper Development Association, [Introduction to Copper: Fact Sheets](https://dev.copper.org/publications/newsletters/innovations/2001/08/intro_fac.html), Table 5: مقاومت ویژهٔ مس در 20°C `0.017241 Ω·mm²/m`; این مقدار fixture ورودی است و با default production `0.0175` یکی نیست.
- Umoette et al., [Dependence of PV Module Temperature on Incident Time-Dependent Solar Spectrum](https://doi.org/10.3390/app10030914), *Applied Sciences* 10(3), 914 (2020), §2 Eq. (1): رابطهٔ سادهٔ خطی NOCT؛ برای fixture تنها حالت ground-mount با offsets صفر استفاده شده است.
- NREL, [PVWatts V8 API documentation](https://developer.nrel.gov/docs/solar/pvwatts/v8/): ثبت ورودی‌ها، نسخهٔ API/SSC، منبع weather و شناسهٔ ایستگاه در نتایج نمونه اهمیت provenance قابل‌بازتولید را نشان می‌دهد؛ هیچ API زنده یا اجرای PVWatts در این follow-up انجام نشده است.
